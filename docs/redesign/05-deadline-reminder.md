# 납기 임박·승인 정체 알림 기획 (초안, 2026-11-05)

> 상태: **기획만** — 구현 전 아래 "결정 필요" 4개를 정한 뒤 착수한다.

## 1. 문제

개발 기간은 디자인 수령 후 최대 2주(행사용 룰)인데, 견적이 **검토·승인·확정 전 단계에서 멈춘 채로** 납기가 다가오는 경우가 있다.
누구 차례인지는 홈 "내 차례"에 이미 나오지만, 사이트에 들어와야만 보인다. 그래서 **사이트 밖(메일)으로 한 번씩 알려준다**.

## 2. 대상 — "멈춘 견적"

| 상태 | 지금 차례 (`getNextAction` 기준) | 알림 받는 사람 |
|---|---|---|
| 대기중 (사업팀 작성) | 개발팀 — 검토 대기 | 관리자(dev) |
| 검토중, 마지막 댓글이 사업팀 | 개발팀 — 검토·승인 | 관리자(dev) |
| 검토중, 마지막 댓글이 개발팀 | 사업팀 — 질문에 답하기 | 작성한 사업팀 + 관리자 참조 |
| 승인 | 사업팀 — 고객 회신 받아 확정 입력 | 작성한 사업팀 + 관리자 참조 |

**제외**: 개발팀이 직접 작성한 대기중 견적(고객 회신 대기용), 보류(on_hold), 숨김, 외주(isExternal), 납기·행사일이 둘 다 없는 견적.
확정 이후(개발 중 납기 임박·초과)는 이미 달력·홈에 빨간 표시가 있으므로 이번 범위에서 제외한다(필요하면 2차).

**기준 날짜**: 요청 납기(`deadline`) → 없으면 행사 시작일(`eventDate`).

## 3. 언제 보내나 — 단계별 1회

개발에 최대 2주가 걸리므로 D-14부터 알린다. 같은 단계에서는 한 번만 보낸다.

| 단계 | 시점 | 제목 머리 |
|---|---|---|
| 1 | 납기 D-14 | `[납기 2주 전]` |
| 2 | 납기 D-7 | `[납기 1주 전]` |
| 3 | 납기 D-3 | `[납기 임박]` |
| 4 | 납기 당일·지남 | `[납기 지남]` (지난 뒤에는 3일마다, 최대 3회) |

- 발송 시각: **평일 오전 9시(KST)** 한 번. 주말에 걸린 단계는 월요일에 몰아서 보낸다.
- 하루에 보낼 건이 여러 개면 **받는 사람당 메일 1통으로 묶는다**(건별 메일 폭탄 방지).

## 4. 메일 내용 (예시)

```
제목: [납기 1주 전] 승인 후 확정 대기 2건 — QuoteMaker

확정 입력이 필요한 견적이 있습니다.

• QT-20261104-001 카카오 판교 포토카드 — 납기 11/20 (D-7), 승인 11/04 이후 대기
• QT-20261102-001 FM 킨텍스 게임 — 납기 12/01 (D-7), 승인 11/02 이후 대기

[견적 바로가기] 링크 (각 건)
```

- 금액은 넣지 않는다(메일 전달·스팸 노출 대비, 사이트에서 확인).
- 말투는 기존 알림 메일과 동일하게 짧게.

## 5. 구현 방안

1. **스케줄**: Vercel Cron — `vercel.json`에 `crons: [{ path: "/api/cron/deadline-reminders", schedule: "0 0 * * 1-5" }]` (UTC 0시 = KST 9시, 평일).
2. **API** `GET /api/cron/deadline-reminders`: `CRON_SECRET` 헤더 검증 → 대상 조회 → 단계 계산 → 받는 사람별로 묶어 `sendEmail` → 발송 기록 저장.
3. **중복 방지**: `Quote`에 `reminderStage Int?`, `reminderSentAt DateTime?` 추가(nullable, 기존 데이터 영향 없음). 상태가 바뀌면(승인·확정 등) 초기화.
4. **차례 판정 재사용**: `src/lib/nextAction.ts`의 `getNextAction`을 그대로 써서 홈 "내 차례"와 메일 내용이 어긋나지 않게 한다.
5. **발송 확인**: 지금 `sendEmail`은 실패해도 조용히 넘어간다. 크론 결과(대상 n건, 발송 성공/실패)를 로그와 응답 JSON에 남기고, 관리자 홈에 "마지막 알림 발송: 11/05 09:00, 3건" 한 줄을 표시한다.
6. **사이트 안 표시**: 홈 "내 차례" 카드에 같은 기준의 `D-7` 배지를 붙여 메일과 화면이 같은 말을 하게 한다.

예상 작업: 1~1.5일 (스키마 2필드 + 크론 API + 메일 템플릿 + 홈 배지 + 테스트).

## 7. 결정 필요

1. **사업팀에게도 메일을 보낼까?** 지금 알림 메일은 관리자(dev)만 받는다. 승인 후 확정 대기는 사업팀 차례라 사업팀 메일이 핵심이다. (redesign 열린 질문 6번과 같은 건)
2. **알림 단계**: D-14 / D-7 / D-3 / 지남 — 이대로 갈지, 줄일지(예: D-7·D-3만).
3. **확정 후 개발 납기 임박**(개발팀 본인 할 일)도 메일로 받을지, 화면 표시로 충분한지.
4. **스팸 대응**: Gmail SMTP로 보내면 스팸함으로 가는 사례가 있었다. 이번에 SPF/DKIM 정리나 Resend 전환을 같이 할지.

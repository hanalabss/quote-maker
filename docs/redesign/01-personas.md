# 01. 페르소나

> 근거: 운영 DB 실측(2026-11-01, 숨김 제외 59건 / 내부 54건), 견적 처리 기록(메모리), 현재 코드.
> 실명 대신 역할 기반 아키타입으로 정리한다. 괄호 안은 실제 대응 계정 유형.

## 실측 요약 (리디자인 근거)

## P1. 현장형 사업팀 담당자 — "빨리 던지고 싶은 사람" (sales, 주 요청자)

- **상황**: 고객사·협력사 전화를 받으며 하루 여러 건을 동시에 굴린다. 견적 요청의 65%를 혼자 낸다.
- **목표**: 고객 통화 직후 10분 안에 요청을 넣고, 오늘 안에 금액을 받아 고객에게 전달.
- **알고 있는 것**: 행사명·일정·장소·인원·프린터 모델·고객이 원하는 체험("찍어서 카드로 뽑아줘").
- **모르는 것**: "인쇄/출력 및 Printer SDK 연동", "UI 개발" 같은 개발 단위. 어떤 조합이 맞는지.
- **현재 고충**
  - 기능 카드(모듈)와 "화면 구성"이 따로 있어 같은 걸 두 번 고르거나 빠뜨린다. 선택 인쇄·KSNET은 두 경로 모두에서 켤 수 있다.
  - 확실하지 않은 기능은 비우고 기타 요청사항에 쓰라는 안내 → 결국 자유 텍스트로 몰리고 개발팀이 해석한다.
  - 개발팀 댓글 질문이 여러 개 섞여 오면 어떤 게 금액에 영향 있는지, 뭘 먼저 답해야 하는지 모른다.
  - 승인 후 고객 확정·일정·시안 전달을 어디에 입력해야 하는지 헷갈린다.
- **필요**: 고객 언어로 된 질문, 지난 비슷한 견적 복제, "내가 지금 해야 할 일" 한 줄.
- **환경**: PC 70%, 외근 중 모바일 확인 30%(회신·상태 확인 위주).

## P2. 협력사/간헐 요청자 — "가끔 와서 매번 처음 같은 사람" (sales, 외부 협력사 포함)

- **상황**: 한 달 1~3건. 키오스크·카드프린터 용어에 익숙하지 않다. 협력사 소속일 수 있다.
- **목표**: 틀리지 않게 한 번에 제출.
- **현재 고충**: 견적 유형(렌탈/재행사/판매) 배율 의미, 옵션 선택 기준을 모른다. 장비 질문에 "모름"을 고를 수 없어 아무거나 고른다.
- **필요**: 예시와 기본값, "모르겠음" 선택지, 제출 전 빠진 것 경고.

## P3. 검토·승인 담당 개발팀장 — "정확하게, 빨리 내보내야 하는 사람" (dev, 관리자 겸)

- **상황**: 모든 견적의 검토·금액 조정·승인·발송 책임. 동시에 매출·파이프라인 정리 담당.
- **목표**: 요청을 받은 당일 확인 질문 또는 승인. 단가 기준(floor·개발 기간 룰·원격 지원 고정 등)을 일관되게 적용.
- **현재 고충**
  - 41% 항목을 손으로 고친다(누락된 UI 개발 추가, 중복 제거, 커스텀 항목 작성).
  - 확인 질문을 댓글로 쓰고, 회신은 시스템 밖에서 받아 다시 반영한다. 무엇이 회신 대기인지 목록에서 안 보인다.
  - 견적 버전(1차·2차·3차 발송) 이력이 없어 고객에게 무엇을 보냈는지 엑셀 파일로만 추적한다.
  - 상태 9개 + 버튼·모달 8종이 상세 페이지 하단에 몰려 있어 잘못 누를 위험(되돌리기 시 확정일 초기화 등)이 있다.
  - 승인 후 확정 건은 노션·폴더·초기 세팅까지 해야 하는데 그 체크가 시스템 밖에 있다.
- **필요**: "내 차례" 큐, 구조화된 확인 요청, 항목 편집기에 기준가·룰 경고, 발송 버전 스냅샷, 확정 후 핸드오프 체크리스트.

## P4. 개발 담당자 — "무엇을 언제까지 만들지만 알면 되는 사람" (dev_staff)

- **상황**: 확정된 행사의 실제 개발 담당. 금액은 보면 안 된다.
- **목표**: 착수일·납기·자료(시안·문구·코드)·장비 정보를 한 화면에서 확인하고 배포 완료를 기록.
- **현재 고충**: 견적 상세가 금액 중심이라 필요한 정보가 흩어져 있다. 자료 수령 여부를 노션·메신저에서 따로 확인한다. 상세 API에서 금액이 차단되지 않는 구멍이 있다(2026-10-15 확인, 미수정).
- **필요**: 금액 없는 "개발 카드" 뷰, 자료 체크리스트, 배포 완료 버튼.

## P5. 경영/관리 관점 — "돈과 일정 전체를 보는 사람" (dev admin의 관리자 모드)

- **상황**: 월말·분기말 매출, 입금(계약금 40/잔금 60), 미진행 정리, 단일 거래처 의존도 확인.
- **목표**: 한 화면에서 이번 달 매출·미수금·정리 대상 확인 후 일괄 처리.
- **현재 고충**: 행사일 경과 건을 하나씩 열어 미진행 처리. 리포트·달력·목록이 각자 다른 기준으로 숫자를 보여준다.
- **필요**: 정리 대상 일괄 처리, 입금 대기 목록, 리포트와 목록 숫자 일치.

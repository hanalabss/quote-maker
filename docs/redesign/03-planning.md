# 03. 기획 — 요구사항

> 범위: 화면 + 흐름 재구성(데이터 모델 변경 허용). 견적 범위는 소프트웨어만이라는 원칙, 기존 단가 정책(유형 배율, floor, 원격 지원 고정 100K, 개발 기간 룰)은 그대로 둔다.

## 1. 목표와 측정

| 목표 | 지표 | 현재 | 목표 |
|------|------|------|------|
| 사업팀이 헷갈리지 않게 요청 | 표준 요청 작성 시간 | 측정 안 됨 | 3분 이내 |
| 요청 = 견적 정합성 | 모듈 미연결(수동) 항목 비율 | 41% | 15% 이하 |
| 회신을 시스템 안으로 | 확인 요청 중 시스템 내 회신 비율 | 측정 불가(댓글 개발45:사업17) | 80% 이상 |
| 정확한 발송 기록 | 승인 금액 스냅샷 보유 견적 | 0% | 100% |
| 정리 업무 단축 | 월말 정리(미진행·완료·입금) 소요 | 건별 처리 | 일괄 10분 이내 |
| 권한 정확성 | dev_staff에게 금액 노출 경로 | 1개(상세 API) | 0 |

측정을 위해 제출 시작/완료 시각, 확인 요청 회신 경로를 기록한다(NFR-6).

## 2. 기능 요구사항

우선순위: **M** 1차 필수 / **S** 1차 권장 / **C** 이후

### A. 사업팀 요청 (P1·P2)
| ID | 요구사항 | 우선 |
|----|----------|------|
| A1 | 시작 방법 선택: 표준 패키지 / 지난 견적 복제 / 빈 요청 | M |
| A2 | 기능 선택과 화면 구성을 **"참여자 체험 단계"** 하나로 통합. 단계는 고객 언어, 순서 변경 가능 | M |
| A3 | 체험 단계 → 견적 항목 자동 매핑. 필수 동반 항목(UI 개발, 인쇄 연동, 테스트·유지보수) 자동 포함, 사용자가 끌 수 없음 | M |
| A4 | 장비·환경 질문마다 "아직 모름" 선택지. "모름"은 확인 요청으로 자동 변환 | M |
| A5 | 프린터가 Smart31/51이면 인쇄 사이즈·카드 종류 질문 숨김(옵셋 CR-80 전제) | M |
| A6 | 제출 전 점검: 누락 필드·모순(예: 인쇄 단계 있는데 프린터 없음) 경고 | M |
| A7 | 금액은 "예상 금액 · 개발팀 검토 후 확정"으로 표기 | M |
| A8 | 임시저장 자동(현재 수동 기능 유지·자동화) | S |
| A9 | 행사 기간 입력 시 개발 가능 일정 안내(디자인 수령 후 최대 2주) | S |
| A10 | 표준 패키지는 개발팀이 관리 화면에서 편집(단계 묶음 + 기본 옵션) | S |

### B. 확인 요청·회신 (P3 ↔ P1)
| ID | 요구사항 | 우선 |
|----|----------|------|
| B1 | 개발팀이 질문을 **확인 요청 카드**로 등록. 그룹: 금액 영향 / 진행 확정 때 알려주시면 됨. 번호는 그룹마다 1부터 | M |
| B2 | 질문 유형: 선택지형(선택지별 금액 변화 선택적 연결) / 단답형 | M |
| B3 | 사업팀은 견적 화면과 홈 "회신 필요"에서 바로 답변. 답변 시 개발팀 알림 | M |
| B4 | 금액 영향 질문이 열려 있으면 승인 시 가드레일(진행은 가능, 사유 남김) | M |
| B5 | 선택지에 금액 변화가 걸린 답변은 개발팀 "반영" 클릭으로 항목에 적용(자동 적용 아님) | S |
| B6 | 요청서에 이미 답이 있는 항목으로 질문을 만들면 경고("요청서에 '프린터: Smart51' 있음") | S |
| B7 | 자유 댓글은 유지(확인 요청과 분리된 "대화" 탭) | M |

### C. 검토·승인·버전 (P3)
| ID | 요구사항 | 우선 |
|----|----------|------|
| C1 | 개발팀이 대기 견적을 열면 자동으로 검토 중 전환(별도 버튼 제거) | M |
| C2 | 항목 편집기: 단계별 그룹, 기준가(floor) 대비 표시, 룰 경고(원격 지원 100K 고정, 개발 기간 상한) | M |
| C3 | 커스텀 항목 작성 시 "모듈로 등록" 제안(미연결 비율 감소) | S |
| C4 | 승인 = 발송본 스냅샷(v1, v2…) 생성 + 운영 메일 발송. Excel은 스냅샷에서 생성 | M |
| C5 | 고객 조정 요청 → 검토로 복귀, 다음 승인은 다음 버전. 버전 비교(항목 ±, 금액 차) | M |
| C6 | 승인 미리보기: 수신자·금액·남은 확인 요청 | S |

### D. 확정·착수 (P1 → P3 → P4)
| ID | 요구사항 | 우선 |
|----|----------|------|
| D1 | 사업팀 "고객 진행 확정" 마법사: 일정 확인, 남은(비금액) 질문 답변, 자료 체크리스트 | M |
| D2 | 자료 체크리스트는 체험 단계에서 자동 생성(배경 선택 → 배경 시안, KSNET → 가맹점 코드 등). 항목별 상태: 받음/예정일/불필요 | M |
| D3 | 개발 납기 자동 제안(난이도 3단계 × 디자인 수령일). 개발팀 수정 가능 | S |
| D4 | 착수 준비 체크리스트(노션 문서·프로젝트 폴더·베이스 코드·개발 담당). 노션 링크 입력란. 기본 담당자 설정값 | M |
| D5 | 개발 담당(dev_staff)용 개발 카드 뷰: 금액 없음, 체험 흐름·장비·자료·납기·배포 완료 | M |
| D6 | 자료 미수령 + 납기 임박 시 경고 배지(사업팀·개발팀 모두) | S |

## 3. 비기능 요구사항

| ID | 요구사항 |
|----|----------|
| NFR-1 | **권한**: dev_staff에게 금액을 내려보내지 않는다. 화면 숨김이 아니라 API 응답에서 제거. 회귀 테스트 포함 |
| NFR-2 | **모바일**: 사업팀 홈·회신·상태 확인·확정 마법사는 400px 폭에서 완결. 요청서 작성은 PC 우선, 모바일은 읽기+간단 수정 |
| NFR-3 | **되돌리기 안전**: 데이터를 지우는 전환(확정→승인 되돌리기 시 일정 초기화 등)은 확인 단계와 이력 기록. 외주 견적은 되돌리기 제한 유지 |
| NFR-4 | **이력**: 상태 전환·금액 변경·버전 생성은 누가/언제/무엇을 남김(현재 이력 댓글 → 활동 로그로 분리) |
| NFR-5 | **호환**: 기존 54건 데이터는 마이그레이션 후 그대로 열람 가능. 기존 견적은 "v1 = 현재 금액"으로 스냅샷 생성 |
| NFR-6 | **계측**: 요청 작성 시작·제출 시각, 확인 요청 생성·회신 시각, 회신 채널 기록 |
| NFR-7 | **접근성**: 키보드 조작, 상태를 색만으로 구분하지 않음(아이콘·텍스트 병기) |
| NFR-8 | **메일**: 승인 메일은 운영 환경에서만 발송. 발송 실패가 API 200으로 숨지 않게 결과를 화면에 표시 |

## 4. 사용자 스토리와 인수 기준 (M 항목)

**US-1 (A1·A2·A3)** 사업팀으로서, 고객이 말한 체험을 그대로 고르면 견적 항목이 알아서 맞춰지길 원한다. 개발 용어를 몰라도 되도록.
- 주어진 "사진 촬영 → 카드 인쇄" 체험을 선택하면, 항목에 카메라·UI 개발·인쇄 연동·테스트가 자동 포함된다.
- 자동 포함 항목은 사업팀이 끌 수 없고 이유가 툴팁으로 보인다.
- 같은 기능을 두 곳에서 고를 수 있는 입력 경로가 없다.

**US-2 (A4·B1·B3)** 사업팀으로서, 모르는 장비 정보는 "모름"으로 넘기고, 개발팀 질문에는 무엇이 금액에 영향 있는지 보고 답하고 싶다.
- "모름" 선택 시 해당 질문이 확인 요청(진행 확정 때 그룹)으로 자동 생성된다.
- 확인 요청은 "금액 영향"과 "진행 확정 때"로 나뉘어 보이고, 금액 영향 그룹이 위에 있다.
- 홈에 회신 필요 개수가 보이고, 클릭하면 질문으로 바로 이동한다.

**US-3 (C4·C5)** 개발팀장으로서, 승인할 때마다 고객에게 나간 내용이 버전으로 남길 원한다.
- 승인 시 v(n) 스냅샷이 생기고 Excel은 그 스냅샷 기준이다.
- 고객 조정 요청 후 재승인하면 v(n+1)이 생기고 v(n)과의 차이가 표시된다.
- 기존 견적은 마이그레이션 시 v1이 생성된다.

**US-4 (D1·D2·D4·D5)** 사업팀과 개발팀으로서, 확정 후 받아야 할 자료와 착수 준비가 한 곳에서 보이길 원한다.
- 확정 마법사 완료 시 자료 체크리스트가 체험 단계 기준으로 생성된다.
- 착수 준비 4항목이 모두 체크되어야 "개발 중"으로 표시된다.
- dev_staff 계정으로 같은 견적을 열면 금액이 화면과 API 응답 어디에도 없다.

**US-5 (E1·E3)** 모든 사용자로서, 로그인하면 내가 지금 처리할 견적만 먼저 보고 싶다.
- 각 견적에 "다음 행동 주체"가 표시되고 홈은 내 역할이 주체인 건만 보여준다.
- 정리함에서 여러 건을 골라 미진행 처리하면 사유가 각 견적에 기록된다.

## 5. 범위 밖 (이번 리디자인에서 하지 않음)

- 단가 정책·유형 배율 변경
- 고객사(외부)에게 직접 견적 링크 공유(사업팀 전달 원칙 유지)
- 렌탈비·하드웨어·소모품 가격(사업팀 소관)
- 노션·GitHub 자동 생성 연동(체크리스트+링크 입력까지만)

## 6. 열린 질문 (결정 필요)

1. **표준 패키지 목록**: 초기 3~5종을 무엇으로 할지(포토카드 기본 / 텍스트 인쇄 / 선택 인쇄 / 카드 발급(입력형) / 결제형?).
2. **반려 상태 유지 여부**: 실사용 5건. "보완 요청(사업팀 차례로 되돌림)"으로 대체할지.
3. **고객 전달일 기록**: 사업팀이 직접 누르게 할지, 승인 = 전달로 간주할지.
4. **협력사 계정**: 외부 협력사 요청자에게 별도 role(금액 열람 범위 등)이 필요한지.
5. **선택지 금액 자동 반영(B5)**: 1차에 넣을지, 수동 반영으로 시작할지.
6. **알림 메일 수신자**: 현재 dev 계정만 수신. 사업팀에도 회신 요청 메일을 보낼지.

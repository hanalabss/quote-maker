# 02. 스토리보드

> 한 건의 행사 견적이 요청부터 완료까지 가는 과정을 5개 장면으로 나눴다. 각 장면은 **현재(AS-IS)** 와 **리디자인(TO-BE)** 을 나란히 둔다.
> 예시 행사: "가을 팝업스토어 포토카드 키오스크", 2주 뒤 3일간, 방문 3,000명, Smart51.
> 와이어프레임은 `storyboard.html`(공유 페이지)에 같은 순서로 있다.

---

## 장면 1. 요청 — 사업팀이 통화 직후 요청을 넣는다 (P1·P2)

**AS-IS**
1. 견적 유형(렌탈/재행사/판매) 선택 → 기본 정보 입력.
2. "기능 선택"에서 개발 단위 카드(키오스크 UI 개발, 인쇄/출력 및 Printer SDK 연동…)를 고른다.
3. "상세 옵션"에서 화면 구성(스플래시→촬영→인쇄…)을 다시 고른다. 선택 인쇄·KSNET은 여기서도 켜진다.
4. 확실하지 않은 건 기타 요청사항에 자유 텍스트로 쓴다.
5. 미리보기 → 제출. 금액이 확정가처럼 보인다.

**TO-BE**
1. **시작 방법 고르기**: ① 표준 패키지(예: 포토카드 기본) ② 지난 견적 복제(재행사·유사 행사) ③ 빈 요청.
2. **행사 정보**: 행사명·기간·장소·인원·요청자. 기간을 넣으면 "개발 가능 일정"이 바로 표시(디자인 수령 후 최대 2주 룰).
3. **참여자 체험 만들기**: "방문객이 키오스크에서 무엇을 하나요?"를 순서대로 쌓는다.
   `시작 화면 → 사진 촬영 → 배경 선택 → 이름 입력 → 카드 인쇄 → 모바일로 받기`
   각 단계는 고객 언어 카드. 견적 항목(모듈)은 시스템이 자동 매핑하고 우측에 "이렇게 견적됩니다"로 보여준다. UI 개발·인쇄 연동처럼 필수 항목은 자동으로 붙어 누락이 생기지 않는다.
4. **장비·환경**: 기기·프린터·네트워크. 모든 질문에 "아직 모름" 선택지. "모름"은 자동으로 확인 요청이 되어 개발팀이 다시 묻지 않는다. Smart31/51은 옵셋 카드 전제라 인쇄 사이즈는 묻지 않는다.
5. **자료·특이사항**: 시안·요청서 첨부, 다국어 디자인 제공 여부, 결제(KSNET) 등 체크형 질문 + 자유 메모.
6. **제출 전 점검**: 빠진 정보 목록과 "예상 금액(개발팀 검토 후 확정)". 제출 후 화면에 "개발팀 검토 중 · 보통 당일 회신".

**성공 기준**: 표준 포토카드 요청 3분 이내, 개발팀의 항목 수동 추가 0건.

## 장면 2. 검토 — 개발팀이 확인 질문을 보내고 사업팀이 답한다 (P3 ↔ P1)

**AS-IS**
- 개발팀이 상세 페이지에서 "검토 시작"을 누르고, 항목을 수정하고, 질문은 댓글 한 덩어리로 작성.
- 사업팀은 메일(스팸함으로 가기도 함)이나 메신저로 알게 되고 답은 메신저로 오는 경우가 많다.
- 개발팀은 회신을 다시 견적에 반영하고 댓글로 정리한다.

**TO-BE**
1. 개발팀이 견적을 열면 자동으로 "검토 중". 별도 "검토 시작" 클릭 없음.
2. 항목 편집기: 체험 단계별로 자동 생성된 항목 + 기준가(floor) 대비 표시 + 룰 경고("원격 지원 고정 100K", "개발 기간 2주 초과").
3. **확인 요청 만들기**: 질문을 카드로 등록. 그룹은 두 가지.
   - **금액에 영향 있음** — 답에 따라 항목이 바뀜. 선택지별 금액 변화를 미리 걸어둘 수 있다(예: "모바일 저장 필요 → +150,000").
   - **진행 확정 때 알려주시면 됨** — 승인을 막지 않음.
4. 사업팀 홈에 "회신 필요 1건" 배지. 사업팀은 선택지를 누르거나 짧게 답한다. 금액 영향 질문의 답은 개발팀 확인 후 항목에 반영.
5. 금액 영향 질문이 모두 닫히면 "승인 가능" 표시. 남은 질문이 있으면 승인 버튼에 가드레일.

**성공 기준**: 회신이 시스템 안에서 이뤄지는 비율 ↑, 사업팀이 "무엇을 먼저 답할지" 묻는 일 0.

## 장면 3. 승인·발송 — 고객에게 나가는 버전을 남긴다 (P3 → P1)

**AS-IS**
- 승인 버튼 → 메일 발송. 무엇을 보냈는지는 엑셀 파일로만 남음. 재문의 시 새 견적을 만들거나 기존 금액을 덮어씀.

**TO-BE**
1. "승인하고 사업팀에 전달" 클릭 시 미리보기(금액·항목·확인 항목 요약·메일 수신자).
2. 승인 시점의 항목·금액을 **발송본 v1**로 고정 저장. Excel은 발송본에서 생성.
3. 고객이 조정을 요청하면 사업팀이 "고객 조정 요청" → 견적이 검토로 돌아가고, 다음 승인은 **v2**. 버전 간 차이(+/- 항목)를 자동 표시.
4. 사업팀 화면: "고객에게 전달하셨나요?" → 전달일 기록. 이후 "고객 회신 기다리는 중 N일째".

**성공 기준**: 모든 발송 금액이 시스템에 남는다. 재문의가 새 견적 번호를 만들지 않는다.

## 장면 4. 진행 확정과 개발 착수 — 사업팀이 확정하고 개발 담당이 받는다 (P1 → P3 → P4)

**AS-IS**
- 확정 모달에서 행사일·개발 마감 입력. 시안·문구·KSNET 코드 등 자료 수령은 노션·메신저에서 따로 관리.
- 노션 문서·프로젝트 폴더·베이스 코드 세팅은 개발팀장이 기억으로 처리.

**TO-BE**
1. 사업팀 "고객이 진행 확정했어요" → 확정 마법사:
   - 행사 일정 확인(요청서 값 미리 채움), 설치일·철수일
   - 장면 2에서 "진행 확정 때 알려주시면 됨"으로 남은 질문을 여기서 답함
   - **자료 체크리스트**: 디자인 시안, 문구, 로고, KSNET 가맹점 코드 등 체험 단계에서 자동 생성. 지금 있는 것은 첨부, 없는 것은 "받을 예정일".
2. 개발 납기는 "디자인 수령 후 난이도별 일수" 룰로 자동 제안(표준 포토카드 3~5일 / 커스텀 연출 1주 / 서버·멀티 2주).
3. 개발팀장 화면에 **착수 준비 체크리스트**: 노션 문서 · 프로젝트 폴더 · 베이스 코드 · 개발 담당 지정(기본값 지정자). 모두 체크되면 "개발 중".
4. 개발 담당(P4)에게 금액 없는 **개발 카드**: 체험 흐름, 장비, 자료 상태, 납기 D-day, 배포 완료 버튼.

**성공 기준**: 자료 미수령으로 납기가 밀릴 때 그 사실이 화면에 먼저 보인다.

---

## 장면 5. 행사·정리 — 완료, 미진행, 입금 (P5)

**AS-IS**
- 행사일 경과 배지를 보고 건마다 열어 미진행 처리. 입금은 상세에서 하나씩 기록. 리포트는 별도 페이지.

**TO-BE**
1. **정리함**: "행사일 지남(회신 없음)" · "완료 처리 대기" · "입금 대기" 세 묶음. 체크 후 일괄 처리(미진행 사유 선택 포함).
2. 완료 처리 시 잔금 입금 예정일을 함께 기록.
3. 리포트·목록·달력은 같은 상태 정의를 쓴다. 숫자를 누르면 해당 견적 목록으로 이동.

**성공 기준**: 월말 정리 10분 이내, 리포트 숫자와 목록 숫자 불일치 0.

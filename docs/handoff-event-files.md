- 진행 순서는 사용자가 지정: 스토리보드 → 설계 → 구현 → 테스트 → 수정.

## 2. 지금 있는 것 (완료 프로그램 기능, 운영 배포됨)

PR #22~#25, main `f7934a1`. 운영 https://quote-maker-alpha.vercel.app

- 견적마다 NAS 행사 폴더 하나를 연결한다. 위치: `/공유폴더/①프로그램 개발/개발팀/[행사 자료]/<행사 폴더>`
- 견적 상세 왼쪽 "완료 프로그램" 칸(`src/components/quote/QuotePrograms.tsx`)이 그 폴더의 **실제 내용**을 보여 준다. NAS에 직접 넣은 파일도 보이고 받을 수 있다.
- API `src/app/api/quotes/[id]/programs/`
  - `GET` 폴더 내용 · `folders` 기존 폴더 목록 · `folder` PUT/DELETE 연결/해제 · `open` 폴더 공유 페이지 · `file` GET/DELETE 받기/지우기 · `init` + `complete` 올리기
- 올리기 흐름: 브라우저 → Supabase `attachments/program-tmp/<견적id>/<uploadId>/` 8MB 조각 → 서버가 이어 붙여 NAS로 전송(NDJSON 진행 스트림) → 크기 확인 → 받기 링크 → 조각 삭제
- 권한: 연결·올리기·지우기 = 개발팀(`dev`, `dev_staff`는 담당 견적만) / 보기·받기·폴더 열기 = 개발팀 + 그 견적을 요청한 사업팀. 기준은 `src/lib/quoteAccess.ts` `canAccessQuote`, `src/lib/programUpload.ts` `canUploadProgram`
- DB: 스키마 변경 없이 `QuoteProgram` 테이블만 쓴다. 규칙은 `src/lib/programAccess.ts` 머리말
  - `size = -1` 행 = 견적 ↔ 폴더 연결 (fileName = 폴더명, shareId/shareUrl = 폴더 공유 링크)
  - `size >= 0` 행 = 파일 받기 링크 (uploadedById 있으면 웹에서 올린 파일)
- NAS 모듈 `src/lib/synology.ts`, 공용 규칙 `src/lib/programUpload.ts`, 테스트 `tests/synology.test.ts`(가짜 NAS 서버) · `tests/programUpload.test.ts`

## 3. 스토리보드 단계에서 사용자에게 확인할 것

기존 기획 문서 형식은 `docs/redesign/02-storyboard.md`, `docs/redesign/storyboard.html` 참고.

1. **누가 올리나** — 사업팀도 디자인 폴더에 올릴 수 있게 하나? (지금은 개발팀만. 사용자 발언은 "견적서 사이트로 업로드할 수 있게끔"까지이고 주체는 말하지 않았다)
2. **하위 폴더 구성** — `디자인` 하나인가, `디자인` + `기타 자료` 처럼 여럿인가, 이름은 고정인가 자유인가. 사용자 표현: "'디자인'이라던가 어떤 특정 자료들 폴더"
3. **기존 "첨부 파일" 칸** — 그대로 두나, NAS로 합치나. 이미 올라가 있는 첨부는 어떻게 하나
4. **폴더가 아직 연결 안 된 견적**에서 사업팀이 올리려 하면 — 자동으로 행사 폴더를 만들까, 개발팀 연결을 기다리게 할까
5. **지우기 권한** — 사업팀이 자기가 올린 시안을 지울 수 있나
6. **기존 행사 폴더들** — 이미 폴더 26개에 파일이 섞여 있다. 하위 폴더는 새로 올리는 것부터만 적용하나

내 추천(사용자 확정 전, 근거는 현재 구조): 하위 폴더 이름은 고정 목록(`디자인`, `기타 자료`)으로 시작, 사업팀은 `디자인`·`기타 자료`에만 올리고 설치 파일 영역은 지금처럼 개발팀만, 지우기는 올린 본인 + 개발팀, 기존 첨부 파일 칸은 당분간 병행.

## 4. 반드시 알아야 할 사실 (실측, 2026-11-11)

- **NAS는 해외 IP를 막는다.** Vercel `icn1` 에서 접속 0.16초, `sin1` 에서 무응답. 그래서 `vercel.json` 이 기본 `sin1` + `functions["src/app/api/quotes/*/programs/**/route.ts"].regions = ["icn1"]` 이다.
  - NAS에 닿는 새 라우트는 **이 패턴 아래(`programs/` 하위)에 두거나 vercel.json 에 패턴을 추가**해야 한다. 안 그러면 운영에서만 "NAS에 접속하지 못했습니다"가 난다(로컬은 한국이라 통과해서 놓치기 쉽다).
  - 라우트의 `export const preferredRegion` 은 적용되지 않았다. 프로젝트 전체를 `icn1` 로 옮기면 견적 상세 API가 170ms → 1.5초로 느려진다. 둘 다 하지 말 것.
  - 확인 방법: `GET /api/quotes/<id>/programs` 응답의 `region` 이 `icn1` 인지. 런타임 로그 머리의 `region=` 은 엣지 리전이라 믿지 말 것.
- NAS: `https://hanapf.synology.me:5500` (DS923plus), 계정 `hana-dev`(관리자 아님, 2단계 인증 없음). CORS 없음 → 브라우저에서 NAS로 직접 못 올린다. Vercel 요청 본문 4.5MB 제한 → Supabase 조각 경유를 유지할 것.
- Synology Sharing API: 없는 링크 삭제 = 코드 401 / `getinfo` 는 없는 id 에도 `success:true`(data 없음), 대상이 지워진 링크는 `status:"broken"` / 같은 이름 올리기 거부 = 414 / 없는 파일 삭제는 오류 없음. `shareLinkAlive` 가 이 동작에 맞춰져 있다.
- 폴더 공유 페이지(`open`)는 하위 폴더까지 탐색된다 — "폴더 열기"만으로도 디자인 폴더에 들어가 받을 수 있다(웹 목록과 별개의 두 번째 경로).
- 공유 링크에는 비밀번호·만료가 없다. 사용자에게 두 번 알렸고 그대로 쓰기로 한 상태.
- 사업팀 계정의 NAS 폴더 접근: 사용자 말로는 열린다("그건 열릴 거야"). 내가 확인하지는 않았다.

## 5. 작업 환경에서 막히는 것 (권한 분류기)

| 동작 | 결과 | 대신 할 것 |
|---|---|---|
| `prisma db push` (운영 DB 스키마) | 막힘 | 스키마 변경 없이 설계하거나, 사용자에게 `! npm run db:push` 요청 |
| `.env` 의 비밀값 읽기 | 막힘 | 비밀값은 사용자가 직접. 스크립트는 `npx tsx --env-file=.env` 로 값만 쓰고 출력하지 않기 |
| 운영에서 남의 계정 쿠키로 접속 | 막힘 | 임시 계정을 DB에 만들어 정상 로그인(아래 6번) |
| `gh pr merge` | 2026-11-11 사용자가 허용함 | 병합 = 운영 배포. 병합 커밋 작성자가 hanalabss 여야 자동 배포 |

그 밖에: Git Bash heredoc(`<<'EOF'`)으로 만든 파일은 `\\` 가 `\` 로 줄어든다 — 역슬래시가 든 스크립트는 Write 도구로 만들 것. 파일이 CRLF 라 문자열 치환 스크립트는 `\r\n` 을 먼저 정규화할 것.

## 6. 테스트 방법 (지난번에 쓴 것, 그대로 재사용 가능)

1. `npm test` (현재 82개) · `npx tsc --noEmit` · `npx next build`
2. 로컬 서버 + 실제 NAS 통합 시험: `npx next dev -p 3111` 을 띄우고, 프로젝트 루트에 임시 `_e2e.ts` 를 만들어 `npx tsx --env-file=.env _e2e.ts` 로 실행. 로컬에서는 `auth-user` 쿠키에 사용자 id 를 넣어 역할별(dev / 견적 요청 사업팀 / 다른 사업팀 / 담당 아닌 dev_staff) 권한을 확인한다. 지난번 54항목 구성: 연결 전 → 폴더 연결 → NAS에 직접 넣은 파일 → 웹 올리기 → 폴더 열기 → 링크 끊김 복구 → 지우기 → 연결 끊기 → 정리.
   - 시험 견적: `QT-20260423-002` (id `cmob2gyrv0001snrfim6y9e1q`, 로운팩토리, completed, dev_staff 담당 아님)
   - 시험 폴더는 **새로 만들어** 쓴다(`_quote-maker 시험` 처럼). 기존 행사 폴더에 시험 파일을 넣지 말 것. 끝나면 폴더·공유 링크·`QuoteProgram` 행을 지우고 행사 폴더 수(26 + 카카오 = 27 예상, 시작 시 실제 수를 먼저 셀 것)가 그대로인지 확인.
3. 화면: Playwright 로 스크린샷(미연결·연결됨·올리기 폼·진행 중·모바일 폭)을 찍어 직접 본다.
4. 운영: 병합 후 Playwright 창에서 사용자가 admin 으로 로그인 → 실제 크기 파일로 올리기·받기(sha256 비교)·지우기. 응답 `region` 과 견적 상세·목록 API 속도(기준: 상세 약 170ms, 목록 약 375~390ms)도 다시 잰다.
5. 사업팀 관점의 운영 확인: 임시 사업팀 계정 + 그 계정 소유 임시 견적을 Prisma 로 만들고(같은 NAS 폴더 연결), 화면에서 정상 로그인해 확인한 뒤 계정·견적·링크를 지운다. 2026-11-11 에 이 방식으로 확인했다.
   - Playwright 의 `confirm` 대화상자는 `page.on('dialog', d => d.accept())` 를 걸어도 도구 호출이 한 번 끊긴다. 끊긴 뒤 상태를 다시 읽어 이어 가면 된다.

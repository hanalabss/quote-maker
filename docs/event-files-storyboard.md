# 행사 자료(디자인·기타 자료) 올리기·받기 — 스토리보드와 설계

작성 2026-11-11. 견적 상세의 "완료 프로그램" 칸을 "행사 자료" 칸으로 넓혀, 시안 등 자료를 NAS 행사 폴더의 하위 폴더에 올리고 받는다.
배경과 실측 사실은 `docs/handoff-event-files.md` 참고.

## 결정 (사용자, 2026-11-11)

| 항목 | 결정 |
|---|---|
| 누가 올리나 | 사업팀(그 견적 요청자) + 개발팀. 완료 프로그램(설치 파일)은 지금처럼 개발팀만 |
| 하위 폴더 | `디자인`, `기타 자료` 두 개 고정. 처음 올릴 때 NAS에 만들어진다 |
| 기존 "첨부 파일" 칸 | NAS로 합친다. 견적 상세의 "파일 추가"를 없애고, 이미 붙어 있는 첨부는 "요청 때 첨부한 파일"로 계속 보인다 |
| 폴더가 연결 안 된 견적 | 자료를 올리면 행사명으로 행사 폴더를 자동으로 만들어 연결한다 |
| 지우기 (기본값으로 진행) | 올린 본인 + 개발팀. 웹에서 올린 파일만 |
| 기존 행사 폴더 (기본값으로 진행) | 그대로 둔다. 하위 폴더는 새로 올리는 것부터 |

범위 밖: 견적 **요청 폼**의 참고 자료 첨부(Supabase, 20MB)는 그대로다. 요청 시점에는 견적도 행사 폴더도 아직 없기 때문.

## 장면

### 1. 사업팀이 시안을 올린다 (폴더가 아직 없는 견적)

```
┌ 행사 자료 ───────────────────────────┐
│ NAS › 개발팀 › [행사 자료]            │
│ 행사 폴더가 아직 없습니다             │
│ [디자인 0] 기타 자료 0  완료 프로그램 0│
│ 아직 올라온 시안이 없습니다.          │
├──────────────────────────────────────┤
│  ⬆ 디자인에 파일 올리기               │
│  끌어다 놓아도 됩니다 · 파일당 500MB까지│
│  처음 올리면 NAS에 행사 폴더가 만들어집니다│
└──────────────────────────────────────┘
```

1. 파일을 여러 개 고르거나 끌어다 놓는다. 올릴 수 없는 형식(실행 파일 등)은 이유와 함께 빠지고 나머지만 남는다.
2. "N개 올리기" → 파일마다 `1/2 서버로 보내는 중 → NAS 폴더로 옮기는 중` 2구간 진행 표시.
3. 첫 파일에서 NAS에 `[행사 자료]/<행사명>/디자인` 이 만들어지고 견적에 연결된다.
4. 끝나면 목록에 `파일명 · 날짜 · 올린 사람 · 크기 · 받기 · 지우기`.
5. 개발 채널 댓글에 `[자료 올림] 디자인 - 파일명…` 이 남는다 (10분 안에 이어 올린 것은 한 댓글에 모인다).

### 2. 개발팀이 받는다

1. 견적 상세 → 행사 자료 → 디자인 칸에서 받기(NAS 공유 링크로 넘어감). "폴더 열기"로 행사 폴더 전체를 열 수도 있다.
2. 개발팀은 모든 자료를 지울 수 있고, "기존 NAS 폴더 연결 / 다른 폴더로 바꾸기 / 연결 끊기"가 보인다.
3. 개발팀이 NAS에 직접 넣은 파일도 같은 칸에 "NAS에 직접 넣음"으로 보이고 받을 수 있다(웹에서 지우기는 불가).

### 3. 개발팀이 수정 시안·완료 프로그램을 올리고 사업팀이 받는다

1. 디자인·기타 자료: 사업팀과 같은 방식. 사업팀 화면에서 개발팀이 올린 파일에는 지우기 버튼이 없다.
2. 완료 프로그램 칸: 개발팀만 올린다(버전·메모). 폴더가 연결돼 있지 않으면 "행사 폴더 연결"이 먼저다.
3. 사업팀은 세 칸 모두 받기만 가능한 파일을 본다. 완료 프로그램 칸에는 올리기·지우기가 없다.

### 4. 막히는 경우

| 상황 | 화면 |
|---|---|
| 반려·미진행 견적 | 올리기 없음. 받을 파일이 있을 때만 칸이 보인다 |
| NAS에서 행사 폴더가 없어짐 | "NAS에서 이 폴더를 찾을 수 없습니다" — 개발팀은 다시 연결, 사업팀은 개발팀에 알림 |
| 같은 이름의 파일 | 덮어쓰지 않고 `yyMMdd-HHmm_파일명` 으로 저장 |
| 행사명과 같은 폴더가 이미 있음 | 남의 행사 폴더일 수 있어 쓰지 않고 `<행사명> (견적번호)` 로 새로 만든다 |
| 여러 개 중 하나가 실패 | 앞의 파일은 올라간 채로 두고, 실패한 파일부터 다시 올릴 수 있게 남긴다 |

## 설계

- **스키마 변경 없음.** 파일 행의 `nasPath` 에 하위 폴더가 그대로 들어간다 (`…/<행사 폴더>/디자인/시안.png`).
- **API** (전부 기존 `api/quotes/[id]/programs/` 아래 → 서울 리전 패턴 그대로)
  - `GET programs` → `files`(행사 폴더 바로 아래, 자료 폴더 제외) + `materials[{dir, files}]`. 파일마다 `canDelete`.
  - `init` · `complete` · `file` 에 `dir` (`""` | `디자인` | `기타 자료`). 목록에 없는 값은 400.
- **권한**

  | 동작 | 완료 프로그램 (`dir` 없음) | 자료 (`디자인`·`기타 자료`) |
  |---|---|---|
  | 보기·받기·폴더 열기 | 견적을 볼 수 있는 사람 | 같음 |
  | 올리기 | 개발팀 (dev_staff 는 담당 견적) | 견적을 볼 수 있는 사람, 반려·미진행 제외 |
  | 지우기 (웹에서 올린 파일만) | 개발팀 | 올린 본인 + 개발팀 |
  | 폴더 연결·변경·해제 | 개발팀 | — (자료를 올리면 자동 생성) |

- **형식**: 자료 = 이미지·시안 원본(ai, psd, eps, indd, pdf, fig, sketch, xd)·문서·영상·소리·글꼴·zip/7z/rar. 실행 파일 불가. 파일당 500MB.
- **삭제 안전장치** (`synology.ts deleteFile`): 행사 폴더 안의 파일(2칸) 또는 자료 폴더 안의 파일(3칸)만. 행사 폴더·자료 폴더 자체와 그보다 깊은 경로는 거부.
- **세션 재시도** (`withSession`): NAS가 세션 없음(106·119)으로 답하면 한 번만 새로 로그인해 다시 한다. 로컬에서 119 가 한 번 났고 재현되지 않아 원인은 미확정.
- **첨부 파일**: 견적 상세의 추가 버튼과 `PATCH addAttachments` 분기를 없앴다. 기존 첨부 데이터·받기 API는 그대로.

## 검증 (2026-11-11, 로컬 + 실제 NAS)

- 단위 테스트 87개, `tsc`, `next build` 통과.
- 로컬 서버 + 실제 NAS 통합 시험 57항목 통과: 권한(요청 사업팀 / 다른 사업팀 / 담당·비담당 dev_staff / dev / 비로그인), 폴더 자동 생성, 같은 이름, 9MB 2조각, 받은 파일 sha256 = 원본, 지우기 권한, 미진행 견적, 같은 행사명 견적의 폴더 분리, 댓글 기록.
- 화면: 사업팀·개발팀·모바일 폭(390px) 스크린샷 확인.
- 시험 폴더·공유 링크·임시 계정·견적 정리, 행사 폴더 수 27개로 시작 전과 같음.
- **아직 안 한 것**: 운영 배포와 운영 검증(리전 `icn1`, 실제 크기 시안 파일, 사업팀 계정 화면).
